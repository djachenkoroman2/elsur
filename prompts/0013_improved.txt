# Задание: пиктограммы и растровые изображения для узлов топологии

## Контекст

Проект — приложение `survivability` (Python 3.11+, `F:\dev\elsur`). Ядро:
задачи 1–3 (`model.py`, `calc.py`, `system_calc.py`, `protection.py`, `io.py`,
`cli.py`); графическая оболочка PyQt6/PySide6 (`survivability/gui.py`:
`MainWindow`, `TopologyCanvas`) и Qt-независимый слой представления
(`survivability/project_codec.py`: `project_to_dict`, `topology_svg`,
`topology_dot`, работа с секцией `gui`).

По заданиям `prompts/0008–0012` GUI умеет: узлы с ролями, координатами,
цветом и фигурами в секции `gui` (`NODE_SHAPES = ("rectangle", "oval",
"trapezoid", "diamond")`, project_codec.py:104; стили узлов — `node_style` /
`set_node_style`, project_codec.py:395-430); оформление связей
(`link_styles`: цвет, тип линии, толщина, стрелки, подписи концов);
экспорт топологии в SVG/DOT.

Текущее ограничение, которое устраняет это задание:

- узел на канвасе — только геометрическая фигура (`_draw_shape`,
  gui.py:828-845): пиктограммы или пользовательского изображения нет;
- в окне свойств узла (панель «Параметры узла», `node_shape_combo`,
  gui.py:1033) нет полей для загрузки растрового файла;
- в формате проекта нет места для изображения узла.

## Требования

### 0. Общие принципы

- **Ядро и формат CLI не меняются**: `NodeInput`/`SystemInput` не трогаем;
  файл проекта по-прежнему открывается CLI (`python -m survivability --file
  project.json`) и даёт те же числа. Изображение узла — **чисто
  отображение**, на расчёт $Q_i$, $Q(S)$, $g^*$ не влияет.
- Изображение хранится в секции верхнего уровня **`gui`** (CLI её игнорирует
  — см. тест `test_cli_ignores_gui_section`) в записи стиля соответствующего
  узла — по образцу существующих ключей `color`/`shape`.
- **Портируемость**: изображение встраивается в файл проекта как data-URI
  (`data:image/png;base64,...`), а не как путь к файлу на диске — проект,
  пересланный другому пользователю, не «теряет» картинки. Файл на диске
  читается один раз, при загрузке.
- Сериализация, санитизация, SVG-рендеринг — в `project_codec.py` (без Qt,
  тестируемо без QApplication); `gui.py` только вызывает хелперы и держит
  кэш `QImage`.
- Секция `gui` — «best effort»: битый base64, нераспознанный MIME-тип,
  слишком большое изображение — игнорируются с сообщением в статусную
  строку, падать запрещено; узел без изображения рисуется как сейчас.
- Жизненный цикл согласован с топологией: переименование узла
  (`rename_node_in_gui`) переносит запись как и остальные стили; удаление
  узла и `prune_gui_section` чистят «осиротевшие» записи — по образцу
  существующей обработки стилей узлов (project_codec.py:374-439).

### 1. Модель: изображение узла

- Новый необязательный атрибут записи стиля узла: **`image`** — строка
  data-URI вида `data:<mime>;base64,<данные>`, где `<mime>` ∈
  `image/png`, `image/jpeg`, `image/bmp` (расширь константу-допуск
  при необходимости; GIF/анимации не требуются).
- Ограничения (зафиксируй константами в `project_codec.py`): максимальный
  линейный размер **512 px** и размер данных **256 КБ** — при превышении
  GUI ресемплирует через `QImage.scaled(..., KeepAspectRatio,
  SmoothTransformation)` и перекодирует в PNG перед сохранением; запись
  больше лимита, загруженная из чужого файла, — санитизация отбрасывает с
  сообщением в статусную строку.
- Хелперы по образцу `node_style`/`set_node_style`
  (project_codec.py:395-430): `node_image(section, name) -> str | None`
  (data-URI или `None`), `set_node_image(section, name, data_uri)` /
  `clear_node_image(section, name)`; валидация — по образцу
  `sanitize_color` (project_codec.py:207): не `data:image/<допустимый>;
  base64,` или нечитаемый base64 → отклонить (`None`). Расширь
  `sanitize_gui_section`, `rename_node_in_gui`, `prune_gui_section` под
  новый ключ (обычно это бесплатно, т.к. ключ живёт внутри записи узла).

### 2. Отрисовка на канвасе

`TopologyCanvas.paintEvent` (gui.py:711+):

- если у узла есть валидное изображение — рисовать его внутри контура
  узла (`drawImage` в ограничивающем прямоугольнике фигуры, масштаб с
  сохранением пропорций, `KeepAspectRatio`, центрирование); фигура и цвет
  узла остаются как **рамка/фон** — вид фигуры не теряется;
- кэш `QImage` по имени узла в `TopologyCanvas` (загрузка из data-URI —
  `QImage.fromData`), инвалидация при `set_node_image` /
  `clear_node_image` и при загрузке проекта; узел без изображения —
  прежний `_draw_shape`;
- хит-тесты, выделение, перетаскивание и подписи узлов не меняются
  (изображение живёт внутри существующего контура).

### 3. Редактирование в интерфейсе — поля загрузки в окне свойств

- В группе «Параметры узла» рядом с «Фигура» и «Цвет…»:
  - кнопка **«Изображение…»** — `QFileDialog.getOpenFileName` с фильтром
    `Изображения (*.png *.jpg *.jpeg *.bmp)`; после выбора — ресемплинг,
    кодирование в data-URI, `set_node_image` + `_mark_dirty()` +
    `canvas.repaint()`;
  - миниатюра-превью (`QLabel` с `setPixmap`, ~64×64) текущего изображения;
  - кнопка **«Убрать»** — `clear_node_image` (скрыта/неактивна, когда
    изображения нет);
  - применение — по паттерну узлов: флаг `self._loading` блокирует сигналы
    при загрузке полей (образцы: `_node_shape_changed`, gui.py:1511;
    `_apply_node_color`).
- Контекстное меню узла (gui.py:622+): пункт «Изображение…» со
  статусом (есть/нет), открывающий тот же диалог; «Убрать изображение» —
  только когда оно задано. Быстрый выбор фигуры в меню — без изменений.
- Ошибки (невалидный файл, чтение не удалось) — диалог/статусная строка,
  расчёт и проект не портятся.

### 4. Экспорт SVG и DOT

- `topology_svg` (project_codec.py): для узла с изображением — элемент
  `<image>` со встроенным data-URI (`href` и `xlink:href` для
  совместимости с браузерами и Inkscape) внутри контура фигуры
  (`<clipPath>` по тому же контуру, чтобы картинка не вылезала за рамку);
  узел без изображения — прежний вывод (текущие тесты SVG не ломаются).
- `topology_dot`: без изменений (Graphviz берёт картинки из внешних
  файлов — в рамках этого задания не нужно; не усложняй формат).

### 5. Формат секции `gui` (зафиксировать в документации)

```json
"gui": {
  ...,
  "nodes": [{"name": "Узел-1", "color": "#cc0000", "shape": "oval",
             "x": 120, "y": 80,
             "image": "data:image/png;base64,iVBORw0KGgo..."}]
}
```

Ключ `image` опционален; повреждённые записи игнорируются санитизацией,
как и для остальных полей стиля.

### 6. Тесты

Добавь (unittest, стиль как в `tests/test_project_codec.py`,
`tests/test_gui_smoke.py`):

- `project_codec`: round-trip `image` (словарь → JSON → словарь без
  потерь); санитизация (битый base64, MIME не из допуска, data-URI сверх
  лимита); `set`/`clear`; переименование узла переносит запись,
  `prune_gui_section` чистит «сироты»;
- SVG: узел с изображением — `<image>` с data-URI и `<clipPath>`; узел без

- CLI-совместимость: файл с `gui.nodes[].image` открывается `io.job_from_json`
  и даёт идентичный расчёт без него; все `examples/example*.json` работают
  без изменений;
- GUI smoke (пропуск без Qt/дисплея, шаблон `_two_node_window`,
  tests/test_gui_smoke.py): кнопка «Изображение…», превью и кнопка
  «Убрать» присутствуют; загрузка тестового PNG (сгенерируй маленький файл
  в памяти через `QImage`/`QPixmap`) задаёт `image`, повторное открытие
  проекта его восстанавливает;
- все существующие тесты зелёные и без установленного PyQt (проверить
  блокировкой импорта через `sys.modules`, как раньше).

## Критерии приёмки

- `python -m unittest discover -s tests -v` — все тесты (старые + новые)
  зелёные; существующие тесты проходят без установленного PyQt;
- CLI работает ровно как раньше: `python -m survivability --file ...` на
  всех `examples/example*.json` и на файле, сохранённом GUI (с
  `gui.nodes[].image`), даёт одинаковые числа;
- сценарий GUI: создать 3+ узла, загрузить изображения (в т.ч. файл
  больше лимита — проверить ресемплинг) → сохранить → открыть заново:
  изображения восстановлены; файл без `image` (старые проекты, примеры)
  открывается с прежним оформлением;
- битая запись `image` (испорченный base64) не роняет открытие проекта —
  узел рисуется фигурой, сообщение в статусной строке;
- экспортированная SVG-схема открывается в браузере: изображения на месте,
  не вылезают за контуры узлов;
- документация (user-guide.md, developer-guide.md, README.md) обновлена,
  формат ключа `image` описан.
