# Задание: связь как редактируемый объект — оформление каналов (цвет, тип линии, стрелки, толщина, подписи концов)

## Контекст

Проект — приложение `survivability` (Python 3.11+, `F:\dev\elsur`). Ядро:
задачи 1–3 (`model.py`, `calc.py`, `system_calc.py`, `protection.py`, `io.py`,
`cli.py`); графическая оболочка PyQt6/PySide6 (`survivability/gui.py`, ~2050
строк: `MainWindow`, `TopologyCanvas`) и Qt-независимый слой представления
(`survivability/project_codec.py`: `project_to_dict`, `topology_svg`,
`topology_dot`, работа с секцией `gui`).

По заданиям `prompts/0008–0011` GUI умеет: узлы с ролями, цветом, фигурами и
координатами в секции `gui`; подписи каналов связи по центру линии
(`gui.link_labels`, редактирование — двойной клик, `_edit_link_label`,
gui.py:1380); выбор/удаление связи кликом и контекстным меню.

Текущее состояние связей, которое устраняет это задание:

- связь — «второсортный» объект: просто пара имён `[a, b]` в `system.links`
  (gui.py:482), без собственной структуры и панели свойств (у узлов панель
  есть — `_build_nodes_tab`, gui.py:920);
- все связи рисуются одинаково: фиксированный цвет `#666666`, сплошная
  линия, ширина 2 px (gui.py:692-693), выделение — красным; стрелок,
  пунктира, выбора толщины нет;
- подпись бывает только одна, по центру линии; подписей у концов связи нет.

## Требования

### 0. Общие принципы

- **Ядро и формат CLI не меняются**: `SystemInput.links` остаётся
  `tuple[tuple[str, str], ...]` — неориентированные пары имён; файл проекта
  по-прежнему открывается CLI (`python -m survivability --file project.json`)
  и даёт те же числа. Расчётная модель неориентированная: стрелки, цвета и
  стили линий — **чисто отображение**, на $Q(S)$ не влияют; не меняй
  семантику графа и `system_calc.py`.
- Все атрибуты оформления связей хранятся в секции верхнего уровня **`gui`**
  (CLI её игнорирует — см. тест `test_cli_ignores_gui_section`) под новым
  ключом **`link_styles`** — по образцу существующего `link_labels`.
- Сериализация, санитизация, SVG/DOT-рендеринг стилей — в `project_codec.py`
  (без Qt, тестируемо без QApplication); `gui.py` только вызывает хелперы.
- Секция `gui` — «best effort»: повреждённые записи стилей игнорируются с
  сообщением в статусную строку, падать запрещено; связь без записи в
  `link_styles` рисуется как сейчас (дефолтный стиль).
- Жизненный цикл метаданных согласован с топологией: переименование узла
  (`_rename_node`) переносит ключи `a`/`b` в записях стилей; удаление связи
  удаляет её запись; удаление узла — записи инцидентных связей;
  `prune_gui_section` чистит «осиротевшие» записи (всё — по образцу
  `link_labels`: `rename_node_in_gui`, `drop_link_from_gui`,
  project_codec.py:374-439).

### 1. Модель оформления связи

У каждой связи (адресуется неориентированной парой имён, как `link_labels`)
есть необязательный набор атрибутов:

- `color` — цвет линии `#rrggbb` (по умолчанию `#666666`);
- `style` — тип линии из множества: `solid` (по умолчанию), `dash`
  (пунктир), `dashdot` (штрих-пунктир);
- `width` — толщина линии в px, целое от 1 до 10 (по умолчанию 2);
- `arrow_start`, `arrow_end` — оформление концов из множества: `none`
  (по умолчанию), `arrow` (стрелка); «начало» — первое имя пары `[a, b]`,
  «конец» — второе; на расчёт не влияет, только отображение;
- `label_start`, `label_end` — текстовые подписи у концов линии
  (по умолчанию пусто). Действующая центральная подпись канала
  (`link_labels`) сохраняется и сочетается с подписями концов.

Реализация в `project_codec.py` по образцу пары `node_style`/`set_node_style`
(project_codec.py:320-355): константы `LINK_LINE_STYLES`,
`LINK_ARROW_STYLES`, `DEFAULT_LINK_STYLE`, `DEFAULT_LINK_COLOR`,
`DEFAULT_LINK_WIDTH`; хелперы `link_style(section, a, b) -> dict`,
`set_link_style(section, a, b, **attrs)`, `drop_link_style(section, a, b)`;
нормализация значений — по образцу `sanitize_color`/`normalize_shape`
(project_codec.py:190-203): неизвестный `style`/`arrow` → дефолт, толщина
вне [1; 10] → clamp, некорректный цвет → дефолт. Расширь
`sanitize_gui_section`, `rename_node_in_gui`, `drop_link_from_gui`,
`prune_gui_section` под новый ключ.

### 2. Отрисовка на канвасе

`TopologyCanvas.paintEvent` (gui.py:685-750):

- линия — `QPen` с цветом, шириной и стилем связи
  (`Qt.PenStyle.SolidLine` / `DashLine` / `DashDotLine`);
- стрелки на концах — заполненные треугольники (`QPolygon`), ориентированные
  по направлению линии, размер пропорционален толщине;
- подписи концов — текст с белым фоном (`drawText` в `OpaqueMode`, как
  центральная подпись), смещённый от точки конца линии наружу так, чтобы не
  перекрывать узел и линию;
- выделенная связь по-прежнему подсвечивается красным (gui.py:714-720),
  поведение выделения не меняется; хит-тест `_link_at` (gui.py:508-524)
  работает для связей любого оформления.

### 3. Редактирование в интерфейсе — подобно узлам

- **Список связей** рядом со списком узлов (или отдельная вкладка
  «Связи»): элементы вида «A — B». Выбор синхронизирован с канвасом в обе
  стороны: клик по линии выбирает элемент списка (сигнал `link_clicked`,
  по образцу `node_clicked` → `_canvas_node_clicked`, gui.py:1675), выбор в
  списке — подсвечивает связь на канвасе.
- **Группа «Свойства связи»** по образцу «Параметры узла»
  (gui.py:920-980): кнопка «Цвет…» с образцом заливки (`QColorDialog`),
  комбобокс «Тип линии» (сплошная / пунктирная / штрих-пунктир), спинбокс
  «Толщина» (1–10), комбобоксы «Стрелка в начале» / «Стрелка в конце»
  (нет / стрелка), поля «Подпись в начале» / «Подпись в конце»
  (QLineEdit), поле/кнопка «Подпись канала» (текущая центральная подпись).
- Применение изменений — по паттерну узлов: флаг `self._loading` блокирует
  сигналы при загрузке полей, изменение пишет через `set_link_style` +
  `_mark_dirty()` + `canvas.repaint()` (образцы: `_node_field_changed`,
  `_apply_node_color`, gui.py:1241-1328).
- Контекстное меню связи (gui.py:610-618): добавь пункт «Оформление…»,
  переводящий фокус на панель свойств связи; «Подпись канала…» и «Удалить
  связь» — без изменений, двойной клик — прежний быстрый ввод подписи.
- Связь, созданная в режиме «Добавить связь», получает дефолтный стиль
  (записи в `link_styles` нет, пока пользователь её не изменит).

### 4. Экспорт SVG и DOT

- `topology_svg` (project_codec.py:513-597): у линии — `stroke` (цвет),
  `stroke-width` (толщина), `stroke-dasharray` для `dash`/`dashdot`
  (подбери читаемые шаблоны); стрелки — SVG-маркеры (`<marker>` в `<defs>`,
  `marker-start`/`marker-end`, для начала — `orient="auto-start-reverse"`);
  подписи концов — `<text>` у соответствующих концов линии. Дефолтный стиль
  даёт текущий вывод (`.e { stroke:#666; stroke-width:2 }`).
- `topology_dot` (project_codec.py:605-621): `color` и `style=dashed/
  bold` ребра — дёшево; стрелки (`arrowhead`/`arrowtail` + `dir=both`) —
  опционально. Граф остаётся неориентированным (`--`).

### 5. Формат секции `gui` (зафиксировать в документации)

```json
"gui": {
  ...,
  "link_labels": [{"a": "Узел-1", "b": "Узел-2", "label": "оптоволокно"}],
  "link_styles": [{"a": "Узел-1", "b": "Узел-2", "color": "#cc0000",
                   "style": "dashdot", "width": 3,
                   "arrow_start": "arrow", "arrow_end": "none",
                   "label_start": "вх. тракт", "label_end": "исх. тракт"}]
}
```

Все поля записи опциональны; неизвестные подключи и повреждённые записи
игнорируются санитизацией.

### 6. Тесты

Добавь (unittest, стиль как в `tests/test_project_codec.py`,
`tests/test_gui_smoke.py`):

- `project_codec`: round-trip `link_styles` (словарь → JSON → словарь без
  потерь); санитизация (неизвестный `style`/`arrow`, толщина 0 и 50, цвет
  не `#rrggbb`); жизненный цикл: `set`/`drop`, переименование узла переносит
  ключи `a`/`b`, удаление узла/связи убирает записи, `prune_gui_section`
  чистит «сироты»;
- SVG: у связи со стилем — `stroke`/`stroke-width`/`stroke-dasharray`,
  маркеры стрелок, тексты `label_start`/`label_end`; связь без стиля —
  прежний вывод; DOT — `color`/`style` ребра;
- CLI-совместимость: файл с `gui.link_styles` открывается `io.job_from_json`
  и даёт идентичный расчёт без него; все `examples/example*.json` работают
  без изменений;
- GUI smoke (пропуск без Qt/дисплея, шаблон `_two_node_window`,
  tests/test_gui_smoke.py:179): список связей и виджеты «Свойства связи»

- все существующие тесты зелёные и без установленного PyQt (проверить

## Критерии приёмки

- `python -m unittest discover -s tests -v` — все тесты (старые + новые)
  зелёные; существующие тесты проходят без установленного PyQt;
- CLI работает ровно как раньше: `python -m survivability --file ...` на
  всех `examples/example*.json` и на файле, сохранённом GUI (с
  `gui.link_styles`), даёт одинаковые числа;
- сценарий GUI: создать 3+ узла и 2+ связи, задать связям цвета, типы
  линий, толщины, стрелки и подписи концов → сохранить → открыть заново:
  всё оформление восстановлено; файл без `link_styles` (старые проекты,
  примеры) открывается с прежним оформлением;
- экспортированная SVG-схема открывается в браузере: цвета линий, пунктир,
  стрелки и подписи концов на месте; подписи читаемы (не перекрывают
  узлы и линии);
- документация (user-guide.md, developer-guide.md, README.md) обновлена,
  формат `link_styles` описан.
