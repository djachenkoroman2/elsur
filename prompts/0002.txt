# Задание: консольное приложение для расчёта живучести узла компьютерной сети

## Контекст

Предметная область — количественная оценка живучести (survivability) узла компьютерной сети
в условиях деструктивных воздействий. Теоретическая основа изложена в презентации
`materials/Слайд Бойко26.09.  Исп.pptx` (слайд 8 «Формальная постановка задачи», слайд 6
«Теория надёжности и резервирования»):

- Система описывается структурной моделью S = ⟨E, L, F⟩, где E — множество элементов (узлов),
  L — связи, F — целевая функция.
- На узел e_i действуют деструктивные воздействия D = {d_1, …, d_m} (отказы и атаки)
  с интенсивностями λ_j.
- Каждое воздействие d_j поражает узел e_i с вероятностью p_ij = P(x_i = 0 | d_j).
- Требуется за период оценивания T найти живучесть узла:
  Q_i = P(x_i(T) = 1) — вероятность сохранения работоспособности узла за время T.
- Рекомендуемая базовая модель — марковская модель «отказ–восстановление»
  (потоки отказов и атак — пуассоновские, восстановление — с интенсивностью μ),
  общая интенсивность ущерба Λ_i = λ_i^(0) + Σ_j λ_j·p_ij.

Перед началом разработки изучи указанную презентацию и при необходимости используй
веб-поиск для уточнения формул марковских моделей надёжности. Если в презентации формула
Q_i не читается полностью (часть формул — картинки), выбери обоснованную общепринятую
формулу на основе марковской модели и явно зафиксируй в документации, какая модель принята.

## Требования к приложению

1. **Язык и окружение**: Python 3.11+, изолированное виртуальное окружение (`venv`)
   в папке проекта. Сторонние зависимости — только при строгой необходимости,
   по умолчанию ограничиться стандартной библиотекой.
2. **Тип**: консольное приложение (CLI), запускаемое как `python -m survivability`
   (или аналогично), без GUI.
3. **Входные данные** — программа должна чётко запрашивать у пользователя
   (интерактивно и/или через файл/аргументы командной строки):
   - интенсивность собственных (случайных) отказов узла λ_i^(0);
   - перечень деструктивных воздействий d_j с интенсивностями λ_j;
   - вероятности поражения p_ij для каждой пары (воздействие, узел);
   - интенсивность восстановления μ (если модель учитывает восстановление);
   - период оценивания T.
   Реализуй валидацию ввода: отрицательные значения, вероятности вне [0; 1],
   λ < 0, T ≤ 0 — отклонять с понятным сообщением.
4. **Расчёт**: по принятой модели вычислять живучесть узла Q_i = P(x_i(T) = 1)
   (и при возможности — вклад каждого воздействия, чтобы видеть доминирующую угрозу).
5. **Вывод**: таблица результатов в консоль + опционально сохранение в файл
   (например, CSV/JSON). Пример входных данных должен быть встроен (режим `--demo`),
   чтобы можно было запустить программу без ручного ввода.
6. **Структура проекта**:
   - `survivability/` — пакет с кодом (модель данных, расчётный модуль, CLI);
   - `tests/` — модульные тесты расчётных формул (pytest, если уместно);
   - `doc/` — документация (см. ниже);
   - `requirements.txt`, `README.md` с инструкцией по запуску.

## Документация (папка `doc/`)

1. Подробное описание работы системы: назначение, архитектура, описание модулей,
   инструкция по установке и запуску, форматы входных/выходных данных.
2. Раздел с расчётными формулами в формате **LaTeX** (в файле `doc/formulas.tex`):
   общая интенсивность ущерба, формула живучести узла Q_i(T), марковская модель
   «отказ–восстановление», каждая переменная — с расшифровкой.
3. Блок-схема алгоритма работы программы в формате **SVG** (файл `doc/algorithm.svg`,
   можно сгенерировать скриптом или написать вручную) с подробным описанием
   в документации: входные данные, этапы обработки, выходные данные, ветвления.

## Отчёт

В конце создай `doc/report.md` — отчёт о проделанной работе: что реализовано,
какие модели и формулы приняты и почему, как проверялась корректность (тесты,
сравнение с эталонными значениями), ограничения и возможные направления развития.

## Критерии приёмки

- Приложение запускается в свежем venv по README и работает в режиме `--demo`.
- Тесты расчётных формул проходят.
- Документация содержит LaTeX-формулы и SVG-схему алгоритма.
- Отчёт заполнен.
