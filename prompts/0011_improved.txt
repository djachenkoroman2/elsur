# Задание: документ «Живучесть системы с учётом топологии» — формулы, алгоритм, инфографика

## Контекст

Проект — приложение `survivability` (Python 3.11+, `F:\dev\elsur`): консольное
ядро (задача 1 — живучесть узла $Q_i$; задача 2 — живучесть системы $Q(S)$
с учётом топологии; задача 3 — выбор защиты $g^*$), графическая оболочка
PyQt6/PySide6, 123 модульных теста (зелёные). Документация после задания
`prompts/0010_improved.txt`: три гайда (`doc/quickstart.md`,
`doc/user-guide.md`, `doc/developer-guide.md`), справочник
`doc/node_types.md`, вывод формул `doc/formulas.tex` → `doc/formulas.pdf`,
блок-схемы `doc/algorithm.svg` (задача 1) и `doc/algorithm_system.svg`
(задачи 2–3).

Что уже есть про задачу 2: раздел «Оценка живучести системы» в
`formulas.tex` (формулы $P(X)$, $Q(S)$, обе $W(X)$, перебор, Монте-Карло,
интервал Уилсона, критичность Бирнбаума) и блок-схема
`algorithm_system.svg`. Чего нет:

- цельного документа, который в одном месте объясняет, **как топология
  (связи $L$) входит в расчёт $Q(S)$**: структурная модель
  $S = \langle E, L, F \rangle$, как связи влияют на $W(X)$ через компоненты
  связности, и чем расчёт отличается для `target = node_fraction` и
  `target = connectivity`;
- полностью просчитанного числового примера «вручную» ($\Lambda_i$ и $Q_i$
  каждого узла, перебор всех векторов состояний с $P(X)$ и $W(X)$, сумма
  даёт $Q(S)$), с числами, совпадающими с реальным выводом CLI;
- поясняющей инфографики по примеру (схема топологии + разбор состояний) —
  отличной от блок-схемы алгоритма.

Код проекта этим заданием **не меняется** — только документация и один
новый SVG.

## Требования

### 1. Новый документ `doc/system_topology.md`

Самодостаточный разбор расчёта $Q(S)$ «от $Q_i$ и топологии к $Q(S)$».
Чек-лист содержания:

1. **Постановка и путь данных**: $S = \langle E, L, F \rangle$,
   $X \in \Omega = \{0,1\}^n$, $Q_i$ берутся из задачи 1 (производный вывод
   $Q_i$ не дублировать — отсылка к `formulas.pdf`); допущение независимости
   узлов и факторизация
   $P(X) = \prod_i Q_i^{x_i} (1 - Q_i)^{1 - x_i}$;
   $Q(S) = P(W(X) \geq W_{\text{доп}}) = \sum_{X:\,W(X)\geq W_{\text{доп}}} P(X)$.
2. **Как входит топология**: списки смежности строит `build_adjacency`
   (`survivability/system_calc.py:47`); связи влияют **только** на
   `target = connectivity` — `node_fraction` связи не учитывает
   (`w_node_fraction`, `system_calc.py:62`); краевые случаи из кода:
   при $n = 1$ полагается $W = x_1$; при пустом $L$ для connectivity
   $W = 0$ при $n \geq 2$.
3. **Обе функции эффективности** с формулами и словесной расшифровкой:
   $W_{\text{node\_fraction}} = \frac{1}{n}\sum_i x_i$ и
   $W_{\text{connectivity}} = \frac{\sum_k \binom{s_k}{2}}{\binom{n}{2}}$
   через компоненты связности работоспособной части графа (в коде — DSU
   «union-find» в `w_connectivity`, `system_calc.py:67`); объяснить разницу
   «узел работоспособен» vs «узел достижим от других».
4. **Два способа расчёта**: точный перебор $2^n$ векторов при
   $n \leq$ `EXACT_MAX_NODES = 20` (`qs_exact`, `system_calc.py:132`);
   Монте-Карло при $n > 20$: $N =$ `monte_carlo_runs` (по умолчанию
   `DEFAULT_MONTE_CARLO_RUNS = 100_000`) бернуллиевских прогонов,
   $\hat{Q}(S) = N^*/N$, доверительный интервал Уилсона 95 %
   ($z = 1{,}959963984540054$, `wilson_interval`, `system_calc.py:120`);
   общий поток случайных чисел с зерном `seed` — воспроизводимость и
   снижение дисперсии сравнения вариантов защиты (задача 3).
5. **Важность узлов**: критичность Бирнбаума
   $I_i = Q(S \mid x_i{=}1) - Q(S \mid x_i{=}0)$ и потенциал
   $\Delta_i^{+} = Q(S \mid x_i{=}1) - Q(S)$ (`NodeImportance`,
   `system_calc.py:200`); в точном режиме суммы накапливаются за один проход
   (`importance_exact`), в режиме Монте-Карло — по `IMPORTANCE_RUNS = 2\,000`
   условным прогонам на узел, всего $2n$ оценок $W(X)$
   (`importance_monte_carlo`); смысл: приоритизация узлов под защиту.
6. **Алгоритм**: пошаговый псевдокод, повторяющий поток `system_qs`
   (`system_calc.py:178`): `node_survivabilities` → `build_adjacency` →
   `TARGET_FUNCTIONS[system.target]` → `qs_exact` / `qs_monte_carlo` →
   `wilson_interval` → `node_importance` — с именами функций и констант.
7. **Полностью просчитанный пример**: `examples/example6_system_line.json`
   (3 узла, линия «ЦОИ — Сервер БД — АРМ оператора»,
   `target = connectivity`, $W_{\text{доп}} = 1/3$): для каждого узла
   посчитать $\Lambda_i$ и $Q_i$ по формуле задачи 1; перебрать все $2^3 = 8$
   векторов состояний с $P(X)$, $W(X)$ и признаком допустимости; суммировать
   $P(X)$ по допустимым — получить $Q(S)$. Числа — **строго из фактического
   вывода CLI** (п. 4), не выдумывать.
8. **Сравнение топологий**: одна таблица $Q(S)$ и важности для трёх случаев
   на одном наборе узлов example6: исходная линия; `target = node_fraction`
   (топология исключена — тот же файл без связей/сменой `target` через
   временный JSON); линия + добавленная связь «ЦОИ — АРМ оператора»
   (треугольник, временный JSON). Вывод: при неизменных $Q_i$ живучесть
   меняется только через $W(X)$, т.е. через топологию.
9. **Расшифровка обозначений** — таблицей (как в `formulas.tex`).
10. **Оформление**: все формулы в `$...$` / `$$...$$`-разметке, как принято
    в проекте; каждую величину при первом упоминании расшифровать;
    источник расшифровок — раздел «Расшифровка обозначений» `formulas.tex`.

### 2. Инфографика `doc/qs_topology.svg`

- Отдельный файл SVG в `doc/`: поясняющая схема примера п. 1.7 — граф из

  копирует блок-схему `algorithm_system.svg`.
