# Задание: графическая оболочка (PyQt) над приложением survivability

## Контекст

Проект — консольное приложение `survivability` (Python, `F:\dev\elsur`).
Реализованы все три задачи формальной постановки (слайд 8 презентации):

- **задача 1** — живучесть узла $Q_i$ (`survivability/calc.py`);
- **задача 2** — живучесть системы $Q(S) = P(W(X) \geq W_{\text{доп}})$
  (`survivability/system_calc.py`, точный перебор при $n \leq 20$, Монте-Карло
  с доверительным интервалом Уилсона при $n > 20$, важность узлов);
- **задача 3** — выбор рационального способа защиты
  $g^* = \arg\max_{g \in G} Q_g(S)$ при $C(g) \leq C_{\text{доп}}$
  (`survivability/protection.py`, общий поток случайных чисел для
  воспроизводимости Монте-Карло).

CLI поддерживает форматы входного JSON: одиночный узел, ключ `system`,
ключ `protection` (см. `doc/documentation.md`, примеры `examples/example*.json`,
73 модульных теста). Требуется добавить **графическую оболочку на PyQt**
поверх существующих утилит, не изменяя их.

## Требования

### 1. Общие принципы

- **Исходные утилиты не менять**: ни код, ни поведение существующих модулей
  (`model.py`, `calc.py`, `system_calc.py`, `protection.py`, `io.py`, `cli.py`,
  `__main__.py`) не изменяются. GUI — отдельный слой, который только
  импортирует и вызывает существующие функции.
- GUI живёт в новом модуле `survivability/gui.py`; запуск —
  `python -m survivability.gui`. Флаг `--gui` добавлять в `cli.py` не нужно.
- **Ядро остаётся независимым от Qt**: `import survivability`,
  `import survivability.cli` и все существующие тесты не должны требовать
  установленного PyQt (в `gui.py` импорты Qt — только внутри модуля).
- Зависимость **PyQt6** — первая и единственная внешняя зависимость проекта;
  вносится в `requirements.txt`. Если для текущего Python (3.14) колёса PyQt6
  недоступны — допускается PySide6 (API-совместимая замена, указать в
  документации, какой пакет используется).

### 2. Редактор проекта

Окно приложения содержит:

- **Редактор узлов**: таблица/панель узлов с полями `NodeInput` — имя,
  $\lambda_i^{(0)}$, $\mu$, $T$ и таблица воздействий ($d_j$, $\lambda_j$,
  $p_{ij}$) на выбранный узел; добавление, удаление, редактирование.
- **Редактор топологии**: канвас (виджет рисования), где узлы —
  подписанные вершины (перетаскивание мышью — на выбор), связи — рёбра;
  добавление связи выбором пары узлов или drag между узлами; удаление узла
  или связи (клавиша Delete / контекстное меню). Визуальное отображение
  невалидных элементов не требуется — ошибки показываются сообщением.
- **Параметры системы**: `w_def`, `target` (`node_fraction` /
  `connectivity`), `monte_carlo_runs`, `seed`.
- **Редактор защиты**: `budget` и список вариантов: имя, `cost`,
  переопределения параметров узлов (`own_failure_rate`, `recovery_rate`,
  `impacts`), `links_added` (выбор пары из существующих узлов).

Вся валидация — через существующие конструкторы моделей (`SystemInput`,
`ProtectionInput`): при `ValidationError` показывать текст ошибки в диалоге,
расчёт не запускать.

### 3. Сохранение проекта

- «Сохранить» / «Открыть» проект в JSON **строго в существующем формате
  CLI** (ключи `system` и опционально `protection`, см. `io.system_from_dict` /
  `io.protection_from_dict`): файл, сохранённый в GUI, открывается в CLI
  (`python -m survivability --file project.json`) и наоборот — без правок.
- «Новый проект», «Сохранить как»; при закрытии с несохранёнными изменениями
  — подтверждение.
- Сборка модели из виджетов — через существующие парсеры (`system_from_dict`,
  `protection_from_dict`), чтобы не дублировать валидацию: GUI строит
  словарь данных и передаёт его в `io`, а не конструирует модель вручную.

### 4. Расчёт из GUI

- Кнопки «Рассчитать $Q(S)$» и «Сравнить варианты защиты»; длительный
  Монте-Карло — без блокировки интерфейса (поток или процесс, прогресс не
  обязателен, но интерфейс не должен «висеть»).
- Панель результатов: $Q(S)$ (и ДИ Уилсона для Монте-Карло), способ расчёта,
  таблица важности узлов ($I_i$, $Q(S|x_i=1)$, $Q(S|x_i=0)$); для защиты —
  сводная таблица вариантов ($C(g)$, допустимость, $Q_g(S)$, $\Delta Q$) и
  выделенный $g^*$ с $\Delta Q$, относительным приростом и эффективностью
  затрат (форматы — как в `io.format_system_report` /
  `io.format_protection_report`, но в виде таблиц виджетов).
- Результаты расчёта можно сохранить через «Экспорт результатов»
  (JSON/CSV теми же функциями `io.save_*`, что использует CLI).

### 5. Экспорт топологии в графический формат

- «Экспорт схемы сети» в **SVG**: собственный рендерер (без новых
  зависимостей, стилистика как у `doc/algorithm.svg`): узлы — скруглённые
  прямоугольники с именами и значениями $Q_i$ (или критичности $I_i$ —
  переключатель «раскраска по: $Q_i$ / важность»), цветовая шкала
  (например, зелёный → красный), рёбра — линии со стрелками-метками;
  подпись легенды. Файл должен открываться в браузере.
- Компоновка: если явных координат нет — раскладка по кругу или решётке.
- Опционально (на выбор, без новых зависимостей): дополнительный экспорт в
  Graphviz DOT — не графический формат, но полезен для внешней отрисовки.

### 6. Тесты

Добавь в `tests/` (unittest, стиль как в существующих):

- круговой обмен проект ↔ JSON: словарь, собранный GUI-моделью проекта,
  проходит через `system_from_dict` / `protection_from_dict` и возвращается
  обратно без потерь (по аналогии с round-trip тестами задач 2–3);
- юнит-тесты SVG-рендерера (без создания `QApplication`): корректный XML,
  имена всех узлов и значения $Q_i$ присутствуют, количество рёбер совпадает
  со связями;
- smoke-тест запуска GUI (`QApplication` + показ главного окна сразу
  закрытым) — пропускать (`skipTest`), если Qt недоступен или нет дисплея;
- существующие 73 теста должны проходить и **без установленного PyQt**
  (проверить запуск `python -m unittest discover -s tests` в окружении
  без Qt — можно симуляцией: блокировка импорта PyQt через `sys.modules`).

### 7. Документация

- `doc/documentation.md`: раздел «Графическая оболочка» — установка PyQt6
  (`pip install -r requirements.txt`), запуск `python -m survivability.gui`,
  описание окон/редакторов, обмен файлами с CLI, экспорт SVG/DOT;
- `README.md`: краткий блок про GUI (запуск, скриншоты — по возможности);
- `doc/report.md`: зафиксировать добавленный GUI-слой и новую зависимость;
- `requirements.txt`: добавить `PyQt6` (или `PySide6` — что реально
  используется), пометив, что ядро расчётов работает без неё.

## Критерии приёмки

- `python -m unittest discover -s tests -v` — все тесты (73 + новые) зелёные;
  существующие тесты проходят без установленного PyQt;
- `python -m survivability ...` (CLI) работает ровно как раньше;
- GUI запускается: создать проект с 3+ узлами и связями, посчитать $Q(S)$,
  сравнить варианты защиты, сохранить проект; сохранённый файл открывается
  CLI и даёт те же числа;
- экспортированная SVG-схема открывается в браузере и содержит подписи узлов
  со значениями;
- документация (documentation.md, README.md, report.md) обновлена.
