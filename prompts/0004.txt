# Задание: доработка режима запуска из JSON и документирование примеров

## Контекст

Проект — консольное приложение `survivability` (расчёт живучести узла сети,
Python 3.11+, только стандартная библиотека), уже реализованное в текущей
рабочей директории `F:\dev\elsur`:

- запуск из JSON-файла уже поддерживается: флаг `--file` в `survivability/cli.py`,
  разбор — `node_from_json()` в `survivability/io.py`;
- формат входного JSON описан в `doc/documentation.md` (раздел 4) и приведён
  в `examples/input.json`;
- тесты: `tests/test_calc.py` (unittest), запуск `python -m unittest discover -s tests -v`;
- документация: `doc/documentation.md`, отчёт `doc/report.md`.

## Требования

### 1. Детальное описание запуска из JSON

Расширь раздел документации `doc/documentation.md`, посвящённый режиму `--file`:

- пошаговое описание: структура файла → проверка формата → команда запуска →
  расшифровка вывода;
- таблица полей JSON: имя поля, тип, обязательность, единица измерения,
  ограничения (`own_failure_rate`, `recovery_rate`, `period`, `impacts[].name`,
  `impacts[].intensity`, `impacts[].defeat_probability`);
- явно укажите: `recovery_rate` можно опустить (тогда 0, восстановления нет),
  все интенсивности и `period` должны быть в одних единицах времени;
- что происходит при ошибках: невалидный JSON, отсутствующее поле, значение вне
  диапазона (код возврата 2, сообщение об ошибке) — продемонстрируй пример
  ошибочного файла и вывод программы.

### 2. Пять примеров запуска с JSON

Добавь в `doc/documentation.md` раздел «Примеры запуска из JSON» с **пятью**
различными сценариями. Для каждого примера обязательны три части:

1. полное содержимое JSON-файла (положи сами файлы в `examples/`, имена вида
   `examples/example1_*.json` … `examples/example5_*.json`);
2. командная строка запуска (Windows и Linux/macOS);
3. краткая расшифровка результата (значение Q_i, что означает в терминах
   предметной области).

Сценарии должны покрывать разные случаи:

1. **Базовый**: один узел, 1–2 воздействия, есть восстановление
   (близко к текущему `examples/input.json`, можно его и использовать);
2. **Без восстановления** (`recovery_rate` опущен или 0): показать экспоненциальное
   падение живучести во времени — подберите T так, чтобы Q_i была заметно ниже
   примера 1 при сопоставимых интенсивностях;
3. **Много воздействий** (5–6 разных типов угроз по мотивам слайда 5 презентации:
   внешние и внутренние нарушители): показать распределение долей и
   доминирующий источник ущерба;
4. **Критически высокий ущерб**: интенсивности таковы, что Q_i низкая (< 0.5)
   даже при восстановлении — вывод о необходимости мер защиты;
5. **Минимальный файл**: только обязательные поля, одно воздействие —
   показать, что опциональные поля можно опускать.

Каждый пример должен быть реально проверен: запусти программу с этим файлом
и приведи в документации фактический вывод (или его основные строки).

### 3. Комментарии в исходном коде

Прокомментируй исходный код на русском языке (сдержанно, только там, где это
действительно помогает):

- docstrings модулей и публичных функций в `survivability/io.py`
  (особенно `node_from_json`, `node_from_dict`) — формат полей, ошибки;
- в `survivability/calc.py` — ссылки на номера формул из `doc/formulas.tex`;
- в `survivability/cli.py` — краткое описание флагов и кодов возврата.

Не переписывай логику, только добавляй/уточняй комментарии и docstrings.
Убедись, что существующие комментарии не противоречат коду.

## Критерии приёмки

- Все 5 примеров реально запускаются: `python -m survivability --file examples/exampleN_*.json` завершается успешно, в документации приведён фактический вывод.
- Пример с ошибочным JSON демонстрирует понятное сообщение и код возврата 2.
- `python -m unittest discover -s tests -v` — все тесты зелёные.
- Документация читается как единое целое, формулы — в LaTeX-разметке ($...$ / $$...$$).
