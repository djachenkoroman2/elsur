выпол# Задание: система документации проекта — реструктуризация doc/ в три раздела

## Контекст

Проект — приложение `survivability` (Python 3.11+, `F:\dev\elsur`): консольное
ядро (задачи 1–3: $Q_i$, $Q(S)$, выбор защиты $g^*$), графическая оболочка
PyQt6/PySide6 (редактор проекта с канвасом, ролями узлов, оформлением
топологии), 123 модульных теста. Документация сейчас размазана:

- `doc/documentation.md` — монолит на 795 строк, 9 разделов («Назначение»,
  «Архитектура и модули», «Установка и запуск», «Входные данные»,
  «Алгоритм работы», «Выходные данные», «Графическая оболочка», «Пример
  сеанса», «Проверка корректности») — в одном файле смешаны материалы
  для новичка, пользователя GUI и разработчика;
- `doc/report.md` — отчёт о реализации (что реализовано, ограничения,
  направления развития), частично дублирует documentation.md;
- `doc/node_types.md` — методический справочник по применимости методики,
  ссылается на `documentation.md` и `formulas.tex`;
- `doc/answ0001.md` — записка о практическом применении и эффекте внедрения;
- `doc/formulas.tex` (+ скомпилированный `formulas.pdf`) — аналитические
  формулы задач 1–3: постановка, марковская модель, перебор, Монте-Карло,
  важность узлов, выбор защиты, расшифровка обозначений;
- `doc/algorithm.svg`, `doc/algorithm_system.svg` — схемы алгоритмов;
- `topology.svg` — пример топологии, лежит в корне репозитория (не на месте);
- `formulas.aux`, `formulas.log` — артефакты сборки LaTeX: в `.gitignore`
  уже игнорируются, но физически лежат в doc/;
- `README.md` — дублирует часть материала из documentation.md.

Код проекта этим заданием **не меняется** — только документация,
`.gitignore` (при необходимости) и перемещение `topology.svg`.

```
  developer-guide.md   # Раздел 3. Руководство программиста
  node_types.md        # методический справочник (существующий, обновить ссылки)
  answ0001.md          # практическое применение (существующий, обновить ссылки)
  formulas.tex         # формулы (существующий)
  formulas.pdf         # собранный из formulas.tex
  algorithm.svg        # схема алгоритма задачи 1
  algorithm_system.svg # схема алгоритмов задач 2–3
  topology.svg         # перенести из корня репозитория
  architecture.svg     # НОВЫЙ: схема слоёв и модулей проекта
  gui_layout.svg       # НОВЫЙ: схема главного окна GUI с подписями элементов
```

`documentation.md` и `report.md` распределить по трём разделам и **удалить**;
`formulas.aux`/`formulas.log` удалить (восстанавливаются сборкой);
`README.md` сделать входной точкой: 1 абзац о назначении, ссылки на три
раздела и формулы — без дублирования их содержимого.

## Требования

### 1. Раздел 1 — Быстрый старт (`doc/quickstart.md`)

Для того, кто получил репозиторий и хочет запустить систему за 5 минут:

- назначение системы — 2–3 абзаца, без формул;
- установка: создание `.venv`, `pip install -r requirements.txt`
  (Windows и Linux/macOS);
- первый запуск: `python -m survivability --demo`, затем
  `--file examples/example6_system_line.json`;
- запуск GUI: `python -m survivability.gui`, что увидеть в окне;
- прогон тестов: `python -m unittest discover -s tests -v`;
- таблица «вопрос → где читать» со ссылками на разделы 2 и 3.

### 2. Раздел 2 — Руководство пользователя (`doc/user-guide.md`)

Максимально подробное описание **каждого элемента GUI** и сценариев работы.
Источник фактов — `survivability/gui.py`, `survivability/project_codec.py`,
раздел «Графическая оболочка» старого documentation.md. Чек-лист покрытия:

- общая компоновка окна (вкладки слева, канвас и результаты справа) —
  со схемой `gui_layout.svg`;
- вкладка «Узлы»: список узлов, поля имя / $\lambda_i^{(0)}$ / $\mu$ / $T$,
  роль (применение и повторное применение), фигура, цвет, диалог
  воздействий; диалог «Добавить узел» и выбор роли из библиотеки;
- вкладка «Система»: $W_{\text{доп}}$, целевая функция
  (`node_fraction` / `connectivity`), прогоны Монте-Карло, зерно ГПСЧ;
- вкладка «Защита»: бюджет, варианты, переопределения параметров,
  добавляемые связи;
- канвас топологии: перетаскивание, добавление связи, удаление
  (Delete/кнопка/контекстное меню), цвет и фигура через контекстное меню,
  подписи каналов (двойной клик / контекстное меню), раскраска по $Q_i$ /
  $I_i$ и её приоритет над ручными цветами;
- меню: «Проект» (новый/открыть/сохранить/экспорт результатов),
  «Экспорт» (SVG/DOT), «Расчёт» (F5/F6), «Настройки» (роли узлов);
- панель результатов: сводка, ДИ Уилсона, таблица важности, таблица
  вариантов с ★ у $g^*$;
- файлы проекта: формат CLI, секция `gui` (что в ней хранится и почему
  CLI её игнорирует), обмен с консолью в обе стороны;
- типовые сценарии пошагово: «создать проект с нуля», «открыть пример
  и посчитать $Q(S)$», «сравнить варианты защиты», «оформить и
  экспортировать схему»;
- формат входного JSON (существующие разделы documentation.md перенести
  сюда): одиночный узел, `system`, `protection`, таблицы полей, примеры.

### 3. Раздел 3 — Руководство программиста (`doc/developer-guide.md`)

Подробное описание кода, технологий и парадигм. Источник фактов —
исходники в `survivability/` и тесты. Чек-лист покрытия:

- архитектура в три слоя (ядро без Qt → кодек проекта → GUI) — со схемой
  `architecture.svg`; почему ядро не зависит от PyQt (проверяется тестом
  с блокировкой импорта);
- по каждому модулю (`model.py`, `calc.py`, `system_calc.py`,
  `protection.py`, `io.py`, `cli.py`, `project_codec.py`, `gui.py`,
  `__main__.py`): назначение, ключевые классы и функции с именами,
  ответственность, взаимосвязи;
- модель данных: `Impact`, `NodeInput`, `SystemInput`, `ProtectionVariant`,
  `ProtectionInput` — валидация в `__post_init__`, единый `ValidationError`;
- алгоритмы: марковская модель «отказ–восстановление» (отсылка
  к `formulas.pdf`), точный перебор и Монте-Карло с ДИ Уилсона, общий
  поток случайных чисел для сравнения вариантов, критерий выбора $g^*$;
- форматы данных: JSON-ключи `system` / `protection` / `gui`, функции
  `io.*_from_dict` и `project_codec.*_to_dict` как единая точка валидации;
- технологии и библиотеки: Python 3.11+, только стандартная библиотека
  в ядре, PyQt6 (fallback PySide6) в GUI, unittest, LaTeX/pdflatex
  для формул; графика — собственные рендереры SVG без зависимостей;
- парадигмы: dataclass-модели с валидацией в конструкторах, разделение
  модели и представления, сигналы/слоты Qt, фоновый расчёт в `QThread`,
  «best effort»-очистка служебных данных (`sanitize_gui_section`),
  функциональный стиль рендереров;
- тестирование: карта «тестовый файл → что проверяется», 123 теста,
  запуск с Qt и без, smoke-тесты GUI;
- статус реализации, ограничения и направления развития — перенести
  из `report.md` (этим раздел замещает report.md целиком).

### 4. Аналитические выражения — LaTeX

- Все формулы в .md-файлах — в LaTeX-разметке (`$...$` / `$$...$$`),
  как принято в проекте; выводы не обрывать, каждую величину при первом
  упоминании расшифровывать (источник расшифровок — раздел
  «Расшифровка обозначений» `formulas.tex`).
- Полный аналитический вывод задач 1–3 — в `doc/formulas.tex`
  (существующие разделы сохранить; при обнаружении расхождений с кодом
  — привести к коду и отметить). Если .tex менялся — пересобрать
  `formulas.pdf` (`pdflatex`, два прогона) без ошибок.

### 5. Графика — отдельные SVG

- Каждая схема/алгоритм — отдельный файл `.svg` в `doc/`, валидный XML,
  открывается в браузере, шрифтовая стилистика как у существующих
  `algorithm*.svg` (Segoe UI, sans-serif).
- Существующие: `algorithm.svg`, `algorithm_system.svg` — оставить,
  при необходимости актуализировать (в algorithm_system.svg появились
  новые возможности GUI — не алгоритмические, схему не трогать, если
  меняется только GUI).
- Новые: `architecture.svg` (слои и модули, импорты) — для раздела 3;
  `gui_layout.svg` (главное окно с подписями областей и элементов) —
  для раздела 2.
- `topology.svg` — перенести из корня репозитория в `doc/`.
- Все схемы встраивать/связывать из соответствующих .md относительными
  ссылками; проверить, что каждая ссылка рабочая.

### 6. Чистка и согласованность

- Удалить: `documentation.md`, `report.md`, `formulas.aux`, `formulas.log`.
- Обновить ссылки во всех сохраняемых файлах: `node_types.md` и
  `answ0001.md` ссылаются на `documentation.md`/`formulas.tex` —
  направить на новые файлы; `README.md` — ссылки на три раздела;
  проверить отсутствие битых ссылок (grep по именам удалённых файлов).
- Формулы, числа тестов (123), версии и команды запуска во всех
  документах — согласовать с текущим состоянием кода.
- `.gitignore` — убедиться, что `doc/*.aux` и `doc/*.log` игнорируются
  (уже есть); больше изменений не требуется.

## Критерии приёмки

- структура `doc/` соответствует целевой; `documentation.md`,
  `report.md`, `*.aux`, `*.log` удалены; `topology.svg` — в `doc/`;
- три гайда существуют, покрывают чек-листы п. 2 и п. 3 (проверка по

- все формулы в .md — в `$...$`-разметке, расшифровки присутствуют;
  `formulas.pdf` собран без ошибок, если .tex менялся;
- все .svg валидны (парсятся XML-парсером) и открываются в браузере;
  ссылки на них из .md рабочие;

  находит битых ссылок;
- `python -m unittest discover -s tests` — все тесты зелёные (код
  не менялся), все примеры `examples/example*.json` работают в CLI;
