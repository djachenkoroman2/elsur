# Задание: развитие графической оболочки — роли узлов, оформление и геометрия топологии

## Контекст

Проект — приложение `survivability` (Python 3.11+, `F:\dev\elsur`). Ядро:
задачи 1–3 (`model.py`, `calc.py`, `system_calc.py`, `protection.py`, `io.py`,
`cli.py`), поверх них графическая оболочка PyQt6/PySide6
(`survivability/gui.py`, ~1450 строк: `MainWindow`, `TopologyCanvas`,
`CalcWorker`) и Qt-независимый слой представления (`project_codec.py`:
`project_to_dict`, `circle_layout`, `topology_svg`, `topology_dot`).
GUI построен по заданию `prompts/0008_improved.txt`: ядро не импортирует Qt,
проект сохраняется строго в формате CLI (ключи `system` / `protection`),
файл GUI ↔ CLI взаимно открывается без правок.

Текущие ограничения GUI, которые устраняет это задание:

- узел создаётся только ручным вводом всех параметров (поля
  `own_failure_rate`, `recovery_rate`, `period`, список воздействий);
- узлы на канвасе и в SVG — всегда скруглённые прямоугольники одного цвета
  (`#cfe2f3`), связи — без подписей;
- координаты узлов (`self.positions`) не сохраняются: при открытии проекта
  `_layout_new_nodes()` раскладывает узлы по кругу (`circle_layout`),
  расстановка теряется;
- CLI-парсер (`io.job_from_json`) читает только ключи `system`/`protection`
  и молча игнорирует прочие ключи верхнего уровня — этим можно воспользоваться
  для хранения GUI-метаданных без нарушения обмена с CLI.

## Требования

### 0. Общие принципы

- **Ядро и формат CLI не меняются**: модули `model/calc/system_calc/
  protection/io/cli/__main__` — без правок; файл проекта остаётся открываемым
  CLI (`python -m survivability --file project.json`) и даёт те же числа.
- Все GUI-метаданные (роли, координаты, цвета, фигуры, подписи связей)
  хранятся в отдельном ключе верхнего уровня **`gui`** рядом с `system` /
  `protection`. Ключ опционален: файлы без него (все существующие
  `examples/example*.json`) открываются как раньше — раскладка по кругу,
  цвета и фигуры по умолчанию.
- Сериализация/десериализация секции `gui` и рендеринг фигур/подписей в SVG —
  в `project_codec.py` (Qt-независимый модуль), чтобы тестироваться без
  QApplication. `gui.py` только вызывает эти функции.
- Секция `gui` — «best effort»: повреждённые или неполные записи
  игнорируются с сообщением в статусную строку, падать запрещено.
- Переименование узла (`_rename_node`) и удаление узла/связи должны
  согласованно обновлять метаданные (координаты, цвет, фигура, подписи
  связей не теряются и не зависают «осиротевшими»).

### 1. Роли узлов: библиотека и выбор при создании

- Встроенная библиотека ролей по умолчанию (код, не редактируется):
  не менее 5 типовых ролей сети, например: сервер, маршрутизатор,
  коммутатор, рабочая станция, датчик/терминал. Каждая роль — имя и
  «примерные» параметры: `own_failure_rate`, `recovery_rate`, `period`
  и список воздействий (`name`, `intensity`, `defeat_probability`),
  типичные для роли (см. `io.demo_node()` по смыслу).
- При добавлении узла («Добавить узел», `_add_node`) диалог содержит
  комбобокс **«Роль»**: «— вручную —» (текущее поведение) + все роли
  из библиотеки и пользовательские. Выбор роли **предзаполняет** числовые
  поля и таблицу воздействий; имя узла по-прежнему вводится вручную
  (предлагаемое по умолчанию — имя роли с номером, например «Сервер-3»,
  уникальное в проекте). После создания параметры узла свободно
  редактируются: роль — шаблон, а не ссылка; расчёт использует параметры
  узла, не роли.
- Выбранная роль запоминается на узле в секции `gui` (поле `role`) и
  показывается в списке узлов/подсказке; при повторном открытии диалога
  редактирования роль подсвечивается как «применённая» (даже если
  параметры уже менялись).

### 2. Редактор пользовательских наборов ролей

- Диалог «Настройки → Роли узлов»: таблица ролей с полями имя,
  `own_failure_rate`, `recovery_rate`, `period`, список воздействий
  (переиспользуй `ImpactsDialog`). Пользователь добавляет, изменяет,
  удаляет свои роли; встроенные роли доступны «копировать в свои».
- Пользовательские роли хранятся в проекте (`gui.roles`) и переносятся
  вместе с файлом; новый проект содержит только встроенную библиотеку.
- Валидация роли — через те же конструкторы (`NodeInput`): при ошибке
  показывать текст и не закрывать диалог с потерей ввода.

### 3. Координаты узлов в файле проекта

- Реальные координаты центров узлов на канвасе сохраняются при «Сохранить»
  в `gui.positions` вида `{"Имя узла": [x, y]}` (массивы чисел, не строки).
- При открытии: позиции из `gui.positions` восстанавливаются; узлы без
  координат и файлы без секции `gui` — по-прежнему `circle_layout`.
  Перетаскивание узла обновляет `positions` и помечает проект изменённым.
- Экспорт SVG (`topology_svg`) и DOT вызываются с фактическими позициями
  проекта, а не пересчитанной раскладкой по кругу.

### 4. Фигуры узлов

- Узел имеет фигуру из множества: `rectangle` (по умолчанию), `oval`,
  `trapezoid`, `diamond`. Выбор — в окне свойств узла (комбобокс «Фигура»)
  и в контекстном меню канваса.
- Отрисовка: на канвасе (`TopologyCanvas.paintEvent`, QPainter) и в
  `topology_svg` (SVG-элементы `rect` / `ellipse` / `polygon` для трапеции
  и ромба; размеры ячейки — существующие `NODE_W`, `NODE_H`). Имя узла и
  значение $Q_i$/$I_i$ остаются читаемыми внутри любой фигуры.
- DOT-экспорт: фигуры маппятся на атрибуты Graphviz (`box`, `ellipse`,
  `trapezium`, `diamond`) — дёшево и без новых зависимостей.
- Неизвестная фигура в файле — тихий откат к `rectangle`.

### 5. Цвет узла

- У каждого узла есть цвет заливки (по умолчанию — текущий `#cfe2f3`).
  Меняется: кнопкой «Цвет…» с образцом в окне свойств узла и из
  контекстного меню канваса (QColorDialog). Цвет хранится в `gui.nodes`
  как `#rrggbb`.
- Приоритет отрисовки: в режиме редактирования — цвет узла; при включённой
  раскраске по результатам ($Q_i$ / важность $I_i$, `_recolor_canvas`)
  тепловая шкала по-прежнему имеет приоритет (поведение не меняется),
  цвет узла применяется снова при сбросе раскраски.
- Цвет фигуры используется и в SVG-экспорте (при отсутствии раскраски
  по значениям).

### 6. Подписи каналов связи

- У каждой связи есть необязательная текстовая подпись (название/тип
  канала: «оптоволокно», «радиорелейный», «VPN» и т.п.). Редактирование:
  диалог/панель свойств связи (выбор связи кликом или в режиме добавления
  связи), двойной клик по линии — быстрый ввод.
- Хранение в `gui.link_labels` как список записей `{"a": имя, "b": имя,
  "label": текст}` (устойчиво к переименованию — ключи обновляются в
  `_rename_node`).
- Подпись рисуется посередине линии (канвас и `topology_svg`) с белым
  контуром/фоном для читаемости поверх линии. Пустая подпись = связь
  без подписи, как сейчас.

### 7. Формат секции `gui` (зафиксировать в документации)

```json
"gui": {
  "roles":   [{"name": "...", "own_failure_rate": 0.01, "recovery_rate": 4.0,
               "period": 1.0, "impacts": [{"name": "...", "intensity": 0.2,
               "defeat_probability": 0.5}]}],
  "positions": {"Узел-1": [320.0, 180.0]},
  "nodes":     {"Узел-1": {"color": "#cfe2f3", "shape": "oval",
                           "role": "Сервер"}},
  "link_labels": [{"a": "Узел-1", "b": "Узел-2", "label": "оптоволокно"}]
}
```

Все подключи опциональны; неизвестные подключи и записи игнорируются.

### 8. Тесты

Добавь (unittest, стиль как в существующих `tests/test_project_codec.py`,
`tests/test_gui_smoke.py`):

- `project_codec`: round-trip секции `gui` (словарь → JSON → словарь без
  потерь); `topology_svg` с фигурами (каждая из 4 фигур даёт ожидаемый
  SVG-элемент) и с подписью связи (текст присутствует); позиции из секции
  `gui` используются в SVG; отсутствие секции → `circle_layout`; повреждённая
  секция не падает, портит не более самой себя;
- CLI-совместимость: файл с секцией `gui` открывается `io.job_from_json` и
  даёт идентичный результат расчёта без неё; все `examples/example*.json`
  работают без изменений;
- поведение метаданных: переименование узла сохраняет координаты/цвет/
  фигуру и переносит подписи связей на новое имя; удаление узла убирает
  его метаданные и подписи инцидентных связей;
- GUI smoke (пропуск при отсутствии Qt/дисплея): добавление узла с ролью
  предзаполняет поля; виджеты «Цвет…»/«Фигура» присутствуют в окне
  свойств узла; диалог ролей открывается;
- все существующие тесты зелёные и без установленного PyQt (проверить
  блокировкой импорта через `sys.modules`, как раньше).

## Критерии приёмки

- `python -m unittest discover -s tests -v` — все тесты (старые + новые)
  зелёные; существующие тесты проходят без установленного PyQt;
- CLI работает ровно как раньше: `python -m survivability --file ...` на
  всех `examples/example*.json` и на файле, сохранённом GUI (с секцией
  `gui`), даёт одинаковые числа;
- сценарий GUI: создать узлы через выбор ролей, расставить на канвасе,
  задать фигуры/цвета/подписи связей → сохранить → открыть заново:
  расстановка, оформление и подписи восстановлены; старый файл без `gui`
  открывается с раскладкой по кругу;
- экспортированная SVG-схема открывается в браузере: фигуры узлов,
  ручные цвета и подписи каналов на месте, позиции совпадают с канвасом;
- документация (documentation.md, report.md, README.md) обновлена,
  формат секции `gui` описан.
