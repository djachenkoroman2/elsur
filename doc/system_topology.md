# Живучесть системы с учётом топологии: формулы, алгоритм, пример

Документ разбирает расчёт живучести системы $Q(S)$ (задача 2) «от входных
данных к числу»: как структурная модель $S = \langle E, L, F \rangle$ и
топология связей $L$ входят в формулу, какие допущения лежат в основе, по
какому алгоритму считает программа и как полученный результат проверить
вручную на малом примере. Аналитический вывод живучести узла $Q_i$
(задача 1, марковская модель «отказ–восстановление») здесь не
дублируется — он дан в [formulas.pdf](formulas.pdf) (источник —
[formulas.tex](formulas.tex)); блок-схема потока задач 2–3 —
в [algorithm_system.svg](algorithm_system.svg).

Реализация — `survivability/system_calc.py` (функции упоминаются по именам).

## 1. Постановка задачи и путь данных

Система описывается структурной моделью $S = \langle E, L, F \rangle$:

- $E = \{e_1, \dots, e_n\}$ — узлы, каждый со своей статистикой отказов
  из задачи 1 ($\lambda_i^{(0)}$, воздействия $d_j$ с $\lambda_j$ и
  $p_{ij}$, интенсивность восстановления $\mu$, период $T$);
- $L$ — неориентированные связи между узлами (пары имён);
- $F$ — целевая функция системы: вид эффективности, который должна
  сохранять система (поле `target` входного JSON).

Состояние системы в момент оценивания — вектор
$X = (x_1, \dots, x_n) \in \Omega = \{0,1\}^n$, где $x_i = 1$, если узел
$e_i$ работоспособен, и $x_i = 0$, если он отказал.

**Допущение независимости.** Состояния узлов принимаются независимыми
случайными величинами с $P(x_i = 1) = Q_i$ (живучесть узла за период $T$
по формуле задачи 1). Поэтому вероятность вектора состояний факторизуется:

$$P(X) = \prod_{i=1}^{n} Q_i^{x_i}\,(1 - Q_i)^{1 - x_i}. \tag{1}$$

Система в состоянии $X$ **допустима**, если её функция эффективности
$W(X) \in [0, 1]$ не ниже допустимого порога деградации
$W_{\text{доп}}$ (поле `w_def`). Живучесть системы — вероятность
допустимого состояния:

$$Q(S) = P\!\left(W(X) \geq W_{\text{доп}}\right)
      = \sum_{X:\,W(X)\geq W_{\text{доп}}} P(X). \tag{2}$$

Топология $L$ входит в (2) **только через $W(X)$**: вероятностная мера
$P(X)$ зависит от узлов, а геометрия сети решает, какие состояния $X$
считаются допустимыми.

## 2. Как топология входит в расчёт

- Перед перебором или прогонами строятся списки смежности графа
  (`build_adjacency`, `system_calc.py:47`): имя каждого узла отображается
  в индекс, каждая связь из `links` добавляется в обе стороны.
- Связи влияют **только** на целевую функцию `connectivity`. Функция
  `node_fraction` смотрит только на число работоспособных узлов и связи
  игнорирует (`w_node_fraction`, `system_calc.py:62`).
- Краевые случаи зафиксированы в коде (`w_connectivity`,
  `system_calc.py:67`): при $n = 1$ полагается $W = x_1$ (единственный
  узел «связен» с самим собой ровно тогда, когда работоспособен); при
  пустом множестве связей $L$ для $n \geq 2$ имеем $W(X) = 0$ (ни одной
  пары узлов не связано).

## 3. Функции эффективности $W(X)$

Реализованы два вида (словарь `TARGET_FUNCTIONS`, `system_calc.py:99`):

**Доля работоспособных узлов** (`target = node_fraction`) — связи не
учитываются:

$$W(X) = \frac{1}{n}\sum_{i=1}^{n} x_i. \tag{3}$$

Здесь «система работает», если работает нужная доля узлов, даже если они
не соединены между собой.

**Доля связных пар** (`target = connectivity`) — топология учитывается
через компоненты связности работоспособной части графа:

$$W(X) = \frac{\sum_k \binom{s_k}{2}}{\binom{n}{2}}, \tag{4}$$

где $s_k$ — размер $k$-й компоненты связности подграфа, индуцированного
работоспособными узлами и связями между ними. Числитель — число пар
узлов, достижимых друг из друга по работоспособным каналам; знаменатель —
число всех пар $\binom{n}{2}$. В коде компоненты выделяются системой
непересекающихся множеств («union-find»): для каждой связи, оба конца
которой работоспособны, выполняется объединение множеств, затем размеры
корней суммируются по формуле (4).

Разница смыслов: в (3) узол «хорош» сам по себе; в (4) — только если он
**достижим** от других работоспособных узлов. Одинокий работоспособный
узел в большой сети даёт вклад $1/n$ в (3), но $0$ в (4) — его изоляция
для системы эквивалентна отказу.

## 4. Два способа расчёта $Q(S)$

Выбор способа делает `system_qs` (`system_calc.py:178`) по числу узлов.

### 4.1. Точный перебор, $n \leq 20$

При $n \leq$ `EXACT_MAX_NODES = 20` сумма (2) вычисляется прямо:
перебираются все $2^n$ векторов $X$ (в коде — целочисленная маска от $0$
до $2^n - 1$), для каждого вычисляются $P(X)$ по (1) и $W(X)$; вероятности
допустимых состояний суммируются (`qs_exact`, `system_calc.py:132`).
Объём $2^{20} \approx 10^6$ векторов — секунды; уже при $n = 21$ время
перебора удваивается и для интерактивного расчёта становится
неприемлемым.

### 4.2. Метод Монте-Карло, $n > 20$

При $n > 20$ выполняется $N =$ `monte_carlo_runs` независимых прогонов
(по умолчанию `DEFAULT_MONTE_CARLO_RUNS = 100\,000`): в каждом состояние
узла $i$ генерируется по схеме Бернулли с вероятностью $Q_i$
(`qs_monte_carlo`, `system_calc.py:150`). Оценка

$$\hat{Q}(S) = \frac{N^{*}}{N},$$

где $N^{*}$ — число прогонов с допустимым состоянием. Точность оценки
задаётся доверительным интервалом Уилсона с доверительной вероятностью
95 % ($z = 1{,}959963984540054$), который корректен и при малых $N^{*}$:

$$\hat{Q}(S) \in
\left[
\frac{\hat{p} + \frac{z^2}{2N} - z\sqrt{\frac{\hat{p}(1-\hat{p})}{N} + \frac{z^2}{4N^2}}}{1 + \frac{z^2}{N}}
\;;\;
\frac{\hat{p} + \frac{z^2}{2N} + z\sqrt{\frac{\hat{p}(1-\hat{p})}{N} + \frac{z^2}{4N^2}}}{1 + \frac{z^2}{N}}
\right], \qquad \hat{p} = \frac{N^{*}}{N}. \tag{5}$$

(`wilson_interval`, `system_calc.py:120`.) В режиме точного перебора
интервал не выводится — оценка детерминирована.

**Общий поток случайных чисел.** Генератор создаётся с зерном `seed`
(поле входного JSON, перекрывается опцией `--seed`) и передаётся во все
вызовы подряд. Оценки разных систем зависимы, и их различия отражают
различия систем, а не случайность потоков — так сравниваются варианты
защиты в задаче 3.

## 5. Важность узлов

Для приоритизации узлов под защиту вычисляется **критичность Бирнбаума** —
доля состояний, в которых отказ узла переводит систему из допустимого
состояния в недопустимое:

$$I_i = Q(S \mid x_i = 1) - Q(S \mid x_i = 0), \tag{6}$$

$$Q(S \mid x_i = 1) = \frac{1}{Q_i}\!\!\sum_{\substack{X:\,x_i=1\\W(X)\geq W_{\text{доп}}}}\!\!P(X),
\qquad
Q(S \mid x_i = 0) = \frac{1}{1 - Q_i}\!\!\sum_{\substack{X:\,x_i=0\\W(X)\geq W_{\text{доп}}}}\!\!P(X), \tag{7}$$

и **потенциал повышения живучести** — прирост $Q(S)$, если узел стал бы
идеальным ($Q_i = 1$):

$$\Delta_i^{+} = Q(S \mid x_i = 1) - Q(S). \tag{8}$$

Результат — запись `NodeImportance` с полями `q_if_up`, `q_if_down`,
`criticality`, `improvement` (`system_calc.py:200`). Способ зависит от
способа оценки $Q(S)$ (`node_importance`, `system_calc.py:292`): при
точном переборе суммы (7) накапливаются за один проход по $\Omega$
(`importance_exact` — те же $2^n$ итераций, что и у `qs_exact`); при
Монте-Карло для каждого узла выполняется $2 \cdot$ `IMPORTANCE_RUNS`
условных прогонов по $2\,000$ (`importance_monte_carlo`): остальные узлы
генерируются случайно, узел $i$ принудительно работоспособен ($x_i = 1$)
или принудительно отказавший ($x_i = 0$). Важность — вспомогательная
диагностика, поэтому точность её оценки на порядок ниже точности $Q(S)$,
а суммарные затраты $2n$ оценок $W(X)$ остаются секундами.

## 6. Алгоритм

Поток вычислений повторяет `system_qs` и связанные функции:

```
вход: SystemInput (узлы E, связи L, W_доп, target, N, seed)
1.  node_survivabilities: для каждого узла Λ_i = λ_i⁽⁰⁾ + Σ_j λ_j·p_ij,
    Q_i по формуле задачи 1 (μ > 0 — с восстановлением, μ = 0 — e^(−Λ_i·T))
2.  build_adjacency: списки смежности по L
3.  effectiveness ← TARGET_FUNCTIONS[target]        # w_node_fraction | w_connectivity
4.  если n ≤ 20 (EXACT_MAX_NODES):                  # qs_exact
        для каждой маски X от 0 до 2^n − 1:
            P(X) ← Π_i (Q_i, если x_i=1, иначе 1−Q_i)
            если P(X) > 0 и effectiveness(X) ≥ W_доп: Q(S) ← Q(S) + P(X)
        метод ← "exact", интервал не строится
    иначе:                                            # qs_monte_carlo
        rng ← Random(seed)
        повторить N раз:
            X ← Bernoulli(Q_i) для каждого i
            если effectiveness(X) ≥ W_доп: N* ← N* + 1
        Q̂(S) ← N*/N; ДИ Уилсона 95 % по формуле (5)
5.  node_importance:                                 # важность всех узлов
        exact    — один проход по Ω с накоплением сумм (7)
        monte_carlo — по IMPORTANCE_RUNS условных прогонов на узла
выход: SystemEstimate(q, method, runs, successes, ci), список NodeImportance
```

## 7. Пример: расчёт «вручную» и сверка с программой

Исходные данные — [examples/example6_system_line.json](../examples/example6_system_line.json):
три узла в линию «ЦОИ — Сервер БД — АРМ оператора», `target = connectivity`,
$W_{\text{доп}} = 1/3$. Поскольку $n = 3 \leq 20$, программа считает
точным перебором, и числа воспроизводимы без зерна Монте-Карло.

### 7.1. Живучести узлов

Общая интенсивность ущерба $\Lambda_i = \lambda_i^{(0)} + \sum_j \lambda_j p_{ij}$,
живучесть $Q_i$ — формула задачи 1 (все три узла имеют $\mu > 0$):

| Узел | $\lambda_i^{(0)}$ | Воздействия $\sum_j \lambda_j p_{ij}$ | $\Lambda_i$ | $\mu$ | $Q_i$ |
|------|------------------:|--------------------------------------:|------------:|------:|------:|
| ЦОИ | 0,01 | $2{,}0{\cdot}0{,}30 + 0{,}1{\cdot}0{,}70 + 0{,}2{\cdot}0{,}50 = 0{,}77$ | 0,780 | 4,0 | 0,838190 |
| Сервер БД | 0,02 | $1{,}5{\cdot}0{,}40 + 0{,}05{\cdot}0{,}90 + 0{,}3{\cdot}0{,}60 = 0{,}825$ | 0,845 | 2,0 | 0,720254 |
| АРМ оператора | 0,05 | $0{,}3{\cdot}0{,}40 + 0{,}2{\cdot}0{,}60 = 0{,}24$ | 0,290 | 1,0 | 0,837076 |

Например, для ЦОИ:
$Q_1 = \dfrac{\mu}{\Lambda_1 + \mu} + \dfrac{\Lambda_1}{\Lambda_1 + \mu}\,e^{-(\Lambda_1 + \mu)T}
     = \dfrac{4}{4{,}78} + \dfrac{0{,}78}{4{,}78}\,e^{-4{,}78} = 0{,}838190$.

### 7.2. Перебор всех $2^3 = 8$ состояний

Состав вектора $X = (x_1, x_2, x_3)$: ЦОИ, Сервер БД, АРМ оператора.
$P(X)$ — по формуле (1); $W(X)$ — по формуле (4): состояние допустимо,
если по работоспособным узлам и связям образуется хотя бы одна пара
($W_{\text{доп}} = 1/3 = \binom{2}{2}\big/\binom{3}{2}$).

| $X$ | Работоспособны | $P(X)$ | $W(X)$ | Допустим |
|:---:|----------------|-------:|-------:|:--------:|
| (000) | — | 0,007375 | 0,000000 | нет |
| (100) | ЦОИ | 0,038202 | 0,000000 | нет |
| (010) | Сервер БД | 0,018988 | 0,000000 | нет |
| (110) | ЦОИ + Сервер БД | 0,098359 | 0,333333 | **да** |
| (001) | АРМ оператора | 0,037891 | 0,000000 | нет |
| (101) | ЦОИ + АРМ оператора | 0,196278 | 0,000000 | нет |
| (011) | Сервер БД + АРМ оператора | 0,097556 | 0,333333 | **да** |
| (111) | все | 0,505351 | 1,000000 | **да** |

Ключевая строка — (101): оба узла работоспособны, но между ними нет
пути (связь проходит через отказавший Сервер БД), поэтому $W = 0$ —
это и есть вклад топологии в формулу.

Сумма по допустимым состояниям:

$$Q(S) = 0{,}098359 + 0{,}097556 + 0{,}505351 = 0{,}701266.$$

### 7.3. Важность узлов

Условные живучести (7) дают критичность Бирнбаума (6):

| Узел | $Q(S \mid x_i = 1)$ | $Q(S \mid x_i = 0)$ | $I_i$ |
|------|--------------------:|--------------------:|------:|
| ЦОИ | 0,720254 | 0,602908 | 0,117346 |
| Сервер БД | 0,973637 | 0,000000 | **0,973637** |
| АРМ оператора | 0,720254 | 0,603710 | 0,116544 |

Сервер БД — точка сочленения линии: при его отказе сеть распадается на
два изолированных узла и $W = 0$ всегда, поэтому $Q(S \mid x_2 = 0) = 0$
и критичность близка к единице. Крайние узлы взаимозаменяемы — их
критичности совпадают почти точно.

## 8. Сравнение топологий на одних узлах

Возьмём те же три узла с теми же $Q_i$ и изменим только структуру связей
(варианты запускались через временные JSON-файлы тем же CLI):

| Структура | `target` | $Q(S)$ | $I$(ЦОИ) | $I$(Сервер БД) | $I$(АРМ) |
|-----------|----------|-------:|--------:|---------------:|--------:|
| линия (2 связи) | connectivity | 0,701266 | 0,117346 | **0,973637** | 0,116544 |
| треугольник (3 связи, добавлена «ЦОИ — АРМ») | connectivity | 0,897544 | 0,351515 | 0,272008 | 0,351024 |
| без связей | node_fraction | 0,992625 | 0,045577 | 0,026363 | 0,045266 |

Три наблюдения:

1. **Топология — множитель живучести.** Узлы не менялись ($Q_i$ те же),
   менялась только геометрия: $Q(S)$ вырос с 0,701266 (линия) до
   0,897544 (треугольник) — резервный путь «ЦОИ — АРМ» делает допустимым
   состояние (101).
2. **Важность — свойство положения узла, а не только его надёжности.**
   В линии критичен центральный Сервер БД ($I \approx 0{,}97$); в
   треугольнике отказ любого одиночного узла оставляет остальные две
   пары связными, и критичности выравниваются до 0,27–0,35.
3. **Вид целевой функции меняет сам масштаб оценки.** Для
   `node_fraction` одинокий работоспособный узел уже допустим
   ($W = 1/3$), поэтому $Q(S) = 0{,}992625$ почти равен вероятности
   «хотя бы один узел жив», а вклад топологии обнуляется — и критичности
   всех узлов невелики. Выбор `target` должен отвечать на вопрос «что
   для системы означает работоспособность»: доля живых элементов или
   сохранение связности.

## 9. Расшифровка обозначений

| Обозначение | Смысл |
|-------------|-------|
| $S = \langle E, L, F \rangle$ | структурная модель системы: узлы, связи, целевая функция |
| $n$ | число узлов системы |
| $L$ | множество неориентированных связей между узлами |
| $e_i$ | $i$-й узел системы |
| $x_i \in \{0,1\}$ | состояние узла $e_i$: 1 — работоспособен, 0 — отказ |
| $X$ | вектор состояний системы, $X \in \Omega = \{0,1\}^n$ |
| $Q_i$ | живучесть узла $e_i$ за период $T$ (задача 1, [formulas.pdf](formulas.pdf)) |
| $P(X)$ | вероятность вектора состояний (формула (1)) |
| $W(X)$ | функция эффективности: доля выполнения целевой функции (формулы (3), (4)) |
| $W_{\text{доп}}$ | допустимый порог деградации (поле `w_def`) |
| $Q(S)$ | живучесть системы: $P(W(X) \geq W_{\text{доп}})$ (формула (2)) |
| $s_k$ | размер $k$-й компоненты связности работоспособной части графа |
| $N$, $N^{*}$ | число прогонов Монте-Карло (успешных) |
| $\hat{Q}(S)$ | оценка $Q(S)$ методом Монте-Карло, $N^{*}/N$ |
| $z$ | квантиль $N(0,1)$: 1,96 для доверительной вероятности 95 % |
| $I_i$ | критичность Бирнбаума узла $e_i$ (формулы (6)–(7)) |
| $\Delta_i^{+}$ | потенциал повышения живучести узла $e_i$ (формула (8)) |
